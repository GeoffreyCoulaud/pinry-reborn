# b502

## 1. Context

The lot `the-data-travels` adds export and import to the web application's `/account` screen, and the API already offers a resumable, chunked import: open with `POST`, send chunks with `PUT .../archive?offset=`, close with `POST .../complete`, the handshake publishing the chunk size and the archive's maximum size. Earlier blocks built the client's upload store (a module-level store above the router, its loop decisions as a pure function in `lib/imports.ts`, #222) and the section's read side with cancel confirmation (#223). What is missing is any UI to start an upload: no file picker, no progress view, no explanation when an upload stops.

## 2. Why

Without this block the store has no consumer, so a user still cannot import an archive from the web application. It also brings the first journey test that drives the whole loop end to end (section, store, real `fetch`) against a server that drops requests, refuses, and reports wrong offsets, which the pure-function tests in `lib/` could not cover. The description does not say why this has to land now beyond completing the lot's import feature.

## 3. How

The section shows the upload this browser tab holds while one exists (it outlives the screen, so navigating away does not kill it and the page warns before unload), and otherwise falls back to the latest import the server reports, offering the picker in terminal states. The file size is checked against the handshake's bound before any request, and the picker stays disabled until the handshake answers, so no oversized import is ever opened and the chunk size is never guessed. Views are a `Record` keyed by the contract's state enum so a new state fails `typecheck`, and refusal codes map to sentences through one table with a generic fallback, reusing the export's lookup generalised to take a table rather than copying it. The description does not name an alternative it rejected (for example driving the upload from the component instead of a store above the router), so the justification against the obvious alternative is implicit at best: the store outliving the screen is what lets an upload survive navigation.
