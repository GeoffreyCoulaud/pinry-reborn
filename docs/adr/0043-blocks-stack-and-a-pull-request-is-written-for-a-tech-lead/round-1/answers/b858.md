# b858

1. **Contexte.** L'API sert déjà l'export et l'import (douze opérations sous `/api/v1/me/exports` et `/api/v1/me/imports`), mais la web application n'en appelle aucune ; le lot `the-data-travels` les amène sur `/account` et dans le task centre, avec un upload d'import qui reprend après une coupure ou un rechargement, et cette PR en est le seul côté API. Il manque deux choses au contrat : les `state` d'export et d'import sont des `string` libres, et la taille de chunk (16 MiB) et la borne d'archive (20 GiB) ne sont publiées nulle part, elles vivent seulement dans `ImportsConfig`.

2. **Pourquoi.** Le client décide à partir de `state` s'il poll, quels boutons il montre et si un lien de téléchargement existe : avec un `string`, TypeScript ne peut pas signaler un état oublié. Une taille codée en dur dans le bundle dériverait d'un déploiement qui abaisse la clé ; la description ne dit pas ce qui casse concrètement dans ce cas (upload refusé, j'imagine, mais elle ne l'écrit pas). C'est nécessaire maintenant parce que les blocs web du lot vont consommer ces champs.

3. **Comment.** Une règle tranche quels champs se ferment : ce qui pilote un comportement devient un `enum` (les deux `state`, via des enums jumeaux de présentation mappés par un `when` exhaustif, sur le modèle de `DownloadStatusDto`, pour qu'un nouvel état du domaine casse le build plutôt que le client), ce qui ne choisit qu'une phrase (`kind`, `failureCode`) reste un `string` ouvert pour qu'une nouvelle valeur ne coûte pas une major. Les bornes suivent le chemin déjà pris par `maxArchiveBytes` : la composition root (`ImportProducers`, `api-application`) copie les deux valeurs d'`ImportsConfig` (module worker, interdit à la présentation par `ArchitectureKonsistTest`) dans un holder `ImportUploadBounds` d'`api-usecases`, injecté dans `HandshakeController` qui les expose dans `LimitsDto` ; l'alternative, un second `@ConfigMapping` sur `imports.*` en présentation, déclarerait chaque défaut deux fois, et aucun module ne gagne de dépendance. Le contrat passe en `18.0.0` parce qu'`oasdiff` lit l'ajout d'un enum de réponse comme une rupture, ce que l'alpha permet (`contract/frozen/` vide) ; la description ne justifie pas le choix du handshake plutôt qu'un endpoint dédié aux imports.
