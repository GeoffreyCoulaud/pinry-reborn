# b779

## 1. Contexte

Le lot « the data travels » apporte l'import et l'export de l'API à l'application web. Le bloc 30 a construit la mécanique d'envoi : un store de niveau module (`imports.ts`) qui vit au-dessus du routeur, et les décisions pures de sa boucle par morceaux (`lib/imports.ts`). Le bloc 34 a donné à la section import de l'écran compte son côté lecture : l'état du dernier import et la confirmation d'annulation. Il manque le point d'entrée : aucun moyen de choisir un fichier, donc le store n'a aucun appelant.

## 2. Pourquoi

Ce bloc ferme la ligne « bloc 30 » de la spécification : l'utilisateur choisit une archive, la voit partir par morceaux et lit en une phrase pourquoi l'envoi s'est mis en pause ou arrêté. Sans lui, le code d'envoi déjà livré reste inaccessible à l'utilisateur. La taille des morceaux et la borne de l'archive viennent de la poignée de main (décision I'), donc un déploiement qui abaisse `imports.max_chunk_bytes` est suivi sans nouveau bundle. La description ne dit pas pourquoi *maintenant* au-delà de l'ordre des blocs du lot.

## 3. Comment

La section décide de l'affichage en un seul endroit : un envoi tenu par le store de l'onglet l'emporte sur la ligne serveur, parce que le store survit à l'écran (on quitte `/account` en cours d'envoi, on revient, la barre de progression est là où en est la boucle). Le sélecteur reste désactivé tant que la poignée de main n'a pas donné les limites, pour ne jamais découper à une taille devinée, et un fichier au-delà de la borne est refusé côté client sans qu'aucune requête ne parte. Les refus deviennent des phrases via une seule table (`importRefusal`, à côté de celle de l'export), typée par `satisfies Partial<Record<…>>` pour qu'une clé mal orthographiée casse le typecheck, avec une phrase générale pour un code inconnu et `Object.hasOwn` contre les clés du prototype. Le sélecteur est un `<input type="file">` natif habillé des `buttonVariants` de HeroUI, faute de contrôle fichier dans HeroUI ; la description ne discute pas d'autre alternative (par exemple laisser l'écran posséder l'état d'envoi plutôt que le store).
