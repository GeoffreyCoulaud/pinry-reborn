# b679

## 1. Contexte

L'API sert déjà l'export et l'import des données d'un utilisateur (`/api/v1/me/exports`, `/api/v1/me/imports`), mais l'application web n'en appelle rien ; le lot « the data travels » doit les amener sur l'écran du compte, avec un envoi d'import qui survit à une coupure réseau et à un rechargement. Dans le contrat, le `state` d'un export ou d'un import est une simple `string`, ce qui ne force aucun écran à traiter tous les états. La taille des morceaux (16 MiB) et la taille maximale d'une archive (20 GiB) n'existent que dans `ImportsConfig`, côté worker, et ne sont publiées nulle part. Cette PR est la seule du lot à toucher `api/` : elle fixe le contrat avant qu'une ligne de code client ne soit écrite.

## 2. Pourquoi

Le comportement du client dépend de l'état (interroger ou non, quels boutons, lien de téléchargement ou pas), et un état inconnu n'a pas de valeur par défaut correcte : un `enum` fermé fait échouer `pnpm run typecheck` sur tout état non traité. Sans les bornes dans le handshake, le client devrait les coder en dur et divergerait d'un déploiement qui les abaisse, ce qui casserait l'envoi par morceaux. C'est le préalable nécessaire au travail client du lot. La description ne dit pas pourquoi cela n'a pas été fait plus tôt, seulement que le lot en a besoin maintenant.

## 3. Comment

Règle : fermé là où le comportement dépend de la valeur (`state` devient un `enum`, via des DTO jumeaux des enums du domaine mappés par un `when` exhaustif, comme `DownloadStatusDto`), ouvert là où seule une phrase en dépend (`kind`, `failureCode` restent des `string`, sinon chaque nouvelle anomalie serait une majeure) ; `ContractSchemaDeclarationTest` verrouille ce partage. Comme `oasdiff` lit un enum de réponse comme fermé, c'est une rupture : le contrat passe en `18.0.0`, admis pendant l'alpha avec `contract/frozen/` vide. Pour les bornes, la couche présentation ne peut pas dépendre de `api-worker-quarkus` : la racine de composition (`api-application`) produit un `ImportUploadBounds` dans `api-usecases`, injecté dans `HandshakeController` qui remplit deux champs obligatoires de `LimitsDto`, chemin déjà emprunté par `maxArchiveBytes`. L'alternative évidente, un second `@ConfigMapping` sur `imports.*` dans la présentation, est écartée car elle déclarerait chaque valeur par défaut deux fois.
