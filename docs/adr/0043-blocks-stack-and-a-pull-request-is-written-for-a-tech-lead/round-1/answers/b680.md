# b680

## 1. Contexte

Le lot « the data travels » ajoute l'export et l'import à l'écran de compte de la web application. L'API expose déjà douze opérations sous `/api/v1/me/exports` et `/api/v1/me/imports`, mais aucun client ne les appelle encore. Il manque deux informations au contrat : les champs `state` des exports et des imports sont de simples chaînes sans ensemble de valeurs déclaré, et les bornes d'upload par morceaux (`imports.max_chunk_bytes` à 16 MiB, `imports.max_archive_bytes` à 20 GiB) ne sont publiées nulle part. C'est le seul bloc du lot qui touche `api/`, et il porte aussi la spécification du lot.

## 2. Pourquoi

La web application qui suit se construit sur ce contrat, et son comportement dépend de `state` : c'est ce champ qui décide s'il faut interroger à nouveau, quels boutons afficher et si un lien de téléchargement existe. Face à un état inconnu, le client n'a aucun comportement par défaut correct. Avec un `enum` fermé, l'union générée permet à un `Record` indexé par l'état de faire échouer `pnpm run typecheck` quand un état n'est pas traité. Pour les bornes, une taille de morceau codée en dur dans le bundle divergerait d'un déploiement qui abaisse la clé : le client doit donc la lire dans le handshake.

## 3. Comment

Pour les états, des jumeaux de présentation des enums du domaine sont ajoutés, sur le modèle de `DownloadStatusDto`. Les mappers les convertissent avec un `when` exhaustif, si bien qu'un état ajouté plus tard au domaine casse le build. Un test de contrat fixe chaque `enum` publié sur les entrées du domaine. Le critère est l'usage qu'en fait le client : `kind` et `failureCode` restent des chaînes ouvertes, parce que le client retombe sur une phrase générale, et que les fermer ferait de chaque nouvelle anomalie une version majeure du contrat (donc, après la bêta, un document gelé de plus à servir). Pour les bornes, `ImportsConfig` vit dans le module worker, dont la présentation ne peut pas dépendre. La racine de composition (`ImportProducers`) les copie donc dans une valeur simple, `ImportUploadBounds` dans `api-usecases`, injectée dans `HandshakeController`, qui publie `maxImportChunkBytes` et `maxImportArchiveBytes` dans `LimitsDto`. L'alternative évidente, un second `@ConfigMapping` sur `imports.*` côté présentation, est écartée parce qu'elle déclarerait chaque valeur par défaut deux fois. Déclarer les enums est un changement cassant selon `oasdiff`, d'où le passage du contrat de `17.0.0` à `18.0.0`, que l'alpha autorise puisque `contract/frozen/` est vide.
