# b598

## 1. Context

The API already serves all twelve export and import operations, but the web application calls none of them; the lot "the data travels" is about to add export and resumable chunked import to the account screen. Two things the client needs are missing from the contract: the export's and the import's `state` are published as plain strings, and the import chunk size and maximum archive size, which live in the `imports.*` configuration, are published nowhere. This block is the bottom of the stack and touches the API side alone; it also carries the lot's specification and one backlog item.

## 2. Why

The client's behaviour depends on the state (whether to poll, which buttons to show, whether a download link exists), and an unknown state has no correct default, so it must be a closed set the client can map exhaustively, with `typecheck` failing on a missed state. The client must also cut chunks at the chunk size and refuse an oversized file before opening an import; hard-coding those values in the bundle would drift from any deployment that changes the keys. It is needed now because blocks 20 (export section) and 30 (upload) up the stack are the first to read the states and the bounds respectively.

## 3. How

Fields are closed by what the client does with them: the two `state` fields drive behaviour and become `enum`s, as presentation twins of the domain enums mapped with an exhaustive `when` (a new domain state breaks the build) and pinned by a contract test, while issue `kind` and `failureCode` only pick a sentence with a fallback and stay open strings, so a new anomaly is not a contract major. The bounds reach the handshake's `LimitsDto` through `api-application`, which produces an `ImportUploadBounds` (in `api-usecases`) from the worker's `ImportsConfig`, the same path `maxArchiveBytes` already takes to the chunk receiver, so the presentation module gains no dependency on the worker. The obvious alternative, a second `@ConfigMapping` on `imports.*` in the presentation module, was rejected because it declares each default twice. Closing the response enums is a break for `oasdiff`, so the contract goes to `18.0.0`, which the alpha allows with `contract/frozen/` empty; the description does not say why the two new `LimitsDto` fields are required rather than optional.
