feat(api): the data states are declared and the handshake publishes the import bounds

The API has served export and import for a while, and the web application calls none of it. The lot *the data travels* makes both reachable from the account screen: export and download an archive, import one through a chunked upload that survives a network cut and a page reload. This pull request is its first block and the only one that touches the API. It changes the contract so the web application can be written against it, and it carries the lot's specification.

## Why

The client needs two things the contract does not say today.

**Which states an export and an import can be in.** `state` is published as a plain string, yet the client's behaviour hangs on it: whether to poll, which buttons to show, whether a download link exists. An unknown state has no sensible default, so the set should be closed and typed. The other string fields of these resources only pick a sentence, and an unknown value there has a correct fallback, so they stay open:

| Field | Published as | Because the client uses it to |
|---|---|---|
| `UserDataExportOutputDto.state` | closed `enum` | decide behaviour, no correct default |
| `UserDataImportOutputDto.state` | closed `enum` | decide behaviour, no correct default |
| issue `kind`, `failureCode` | open `string` | choose a sentence, with a general one as fallback |

Closing `kind` would make every new anomaly a contract major, which after beta means one more frozen document to keep serving.

**How to cut an upload.** The chunk size (16 MiB) and the archive bound (20 GiB) exist only in the server's `imports.*` configuration. A client that hard-codes them drifts from a deployment that lowers them.

## How

- **The states become presentation twins of the domain enums**, `UserDataExportStateDto` and `UserDataImportStateDto`, the shape `DownloadStatusDto` already has. The mappers map exhaustively, so a domain state added later fails the build rather than reaching the wire undeclared.
- **The contract takes a major, to 18.0.0.** `oasdiff` reads an enum on a response as closed, so declaring one is a break for any client that treated the field as open. The alpha allows it and `contract/frozen/` is still empty.
- **`LimitsDto` gains `maxImportChunkBytes` and `maxImportArchiveBytes`**, beside the image limits a client already checks before sending.
- **The bounds reach the handshake without a new module dependency.** `ImportsConfig` lives in the worker module, which the presentation module may not depend on. `ImportProducers`, in `api-application`, already hands `maxArchiveBytes` to the chunk receiver; it now also produces an `ImportUploadBounds` from `api-usecases`, which `HandshakeController` injects. A second `@ConfigMapping` on `imports.*` in the presentation module would have declared every default twice.

The tests pin both halves: the published contract lists exactly the domain's states and keeps `kind` a plain string, and the handshake answers a test profile's overridden `imports.*` values rather than the defaults.

The block also files one backlog item: the contract's other string fields, `reasonCode` and `DownloadStatusDto` among them, have not been weighed as open or closed by the same test.
