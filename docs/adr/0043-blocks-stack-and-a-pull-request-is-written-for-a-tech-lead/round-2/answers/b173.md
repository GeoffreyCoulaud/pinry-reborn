# b173

## 1. Contexte

Cette PR est le bloc de clôture du lot « the data travels ». Elle vient au-dessus d'une pile de neuf PR (#228) qui n'est pas encore fusionnée, et la revue holistique de cette pile a relevé 1 MAJOR et 11 MINOR. Dans la web app, l'envoi d'une archive d'import vit dans un store de module placé au-dessus du router, et tant qu'il contient un envoi, celui-ci masque la ligne d'import renvoyée par le serveur (section import du compte et task centre). Il manquait un moyen de reconnaître que le serveur avait déjà avancé : une réponse au `POST .../archive/complete` perdue sur le réseau, ou un `IMPORT_NOT_AWAITING_ARCHIVE` reçu par l'onglet perdant quand deux onglets envoient le même import, arrêtaient l'envoi alors que l'import était déjà `PENDING`/`RUNNING`.

## 2. Pourquoi

Dans ces deux cas, l'onglet gardait un envoi arrêté par-dessus un import vivant, avec un seul contrôle, Cancel, qui aurait fait un `DELETE` de l'import en cours. C'est une perte de travail côté serveur, et c'est le constat MAJOR. Le correctif doit être fait maintenant, avant toute fusion, pour que les relecteurs des neuf PR de la pile ne relisent pas un comportement d'envoi qui n'existe plus. Il sert aussi à corriger le handoff, le backlog et la spécification du lot avant qu'ils ne fassent foi.

## 3. Comment

`IMPORT_NOT_AWAITING_ARCHIVE` change de sens : il signifie désormais « le serveur a avancé », l'envoi se termine et la ligne du serveur prend le relais. La requête de clôture suit maintenant le même calendrier de nouvelles tentatives que les chunks, décidé par une seule fonction pure (`nextStep` dans `lib/imports.ts`, donc dans le périmètre de couverture à 100 %), si bien qu'une clôture perdue est renvoyée et, si la première était arrivée, la seconde reçoit le 409 et passe la main. Une seule règle, « le store ne cède qu'une fois la ligne du serveur relue », corrige aussi trois MINOR (état obsolète affiché pendant un aller-retour, refus du Cancel invisible, prune du resume record). La description ne compare pas explicitement avec l'alternative évidente, par exemple un garde contre les deux onglets, dont la limite est seulement notée comme acceptée par l'opérateur (« Q1 »).
