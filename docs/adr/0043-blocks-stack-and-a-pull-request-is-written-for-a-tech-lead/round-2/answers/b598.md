# b598

## 1. Context

The API already serves twelve export and import operations under `/api/v1/me/exports` and `/api/v1/me/imports`, but the web application calls none of them. The lot "the data travels" will bring them to the account screen and the task centre, and this PR is its first block: a contract-only change (plus the lot's specification) that the later client blocks build on. Two things are missing from the contract: the export and import `state` fields are plain strings, and the import's chunk size (16 MiB) and archive bound (20 GiB) are published nowhere, living only in the worker's `ImportsConfig`.

## 2. Why

The client decides from `state` whether to poll, which buttons to show and whether a download link exists, and an unknown state has no correct default, so the contract must promise the full set. Hard-coding the upload bounds in the bundle would drift from any deployment that lowers `imports.max_chunk_bytes` or `imports.max_archive_bytes`. Block 20 (export section) reads the states first and block 30 (upload) reads the bounds, so they need the contract now. The description does not say what breaks today, as no client uses these endpoints yet.

## 3. How

One rule picks open or closed: a field whose value drives client behaviour becomes a closed `enum` (the two `state`s, as presentation twins of the domain enums mapped by an exhaustive `when`, with a test per twin so a new domain state fails the build), while fields that only drive a sentence with a fallback (`kind`, `failureCode`) stay open strings so each new anomaly is not a contract major. Closing a response enum is a break for `oasdiff`, so the contract goes from 17.0.0 to 18.0.0, which the alpha allows (`contract/frozen/` is empty). The two bounds join the handshake's `LimitsDto` by the path `maxArchiveBytes` already takes: `ImportProducers` in `api-application` reads the worker's `ImportsConfig` and produces an `ImportUploadBounds` in `api-usecases` for `HandshakeController`, so no module gains a dependency on the worker. The obvious alternative, a second `@ConfigMapping` on `imports.*` in the presentation module, is rejected because it would declare each default twice.
