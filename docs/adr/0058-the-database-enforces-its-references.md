# 0058. The database enforces its references

Status: Accepted
Date: 2026-10-11
Amends: `docs/adr/0056-data-shapes-are-decided-in-the-specification.md`, decision 7.2 ("declares `ON DELETE CASCADE`").
Specification: `docs/specs/2026-10-11-the-database-enforces-its-references.md`.

## Context

SQLite enforces no foreign key unless `foreign_keys` is on, and it is off: every key Ebean declares is decoration. The
code deletes dependent rows by hand, in an order a comment states, and two periodic sweeps collect what it misses.
ADR 0056, decision 7.2, flattens the migration history and turns the pragma on with `ON DELETE CASCADE`. Discuss on
2026-10-10 and 2026-10-11 found that a cascade on every key is wrong for one of them, and settled how the model says
which action each key takes. Decisions 1 to 7 are the operator's; 8 to 10 are the lead's, after the specification
review.

## Decision

1. **A row that has no meaning without its parent is deleted with it** (`CASCADE`): what a user owns, a pin's media,
   download, join rows and duplicate pairs, a media's frames, a board's collections, an import's issues.
2. **A reference that only names someone is emptied** (`SET NULL`): `pins.publisher_id`. Deleting a person removes
   their credits; no route deletes a person today.
3. **The code deletes the row it targets and the database deletes the rest.** The repository methods that delete
   dependents go, and so do the sweeps that collect orphan frames and pairs. Files on disk stay the code's.
4. **Each relation of a model declares its action** (`@DbForeignKey(onDelete = ...)`), and a Konsist rule refuses
   one that does not, or that declares no constraint.
5. **A table is named after its model**: the class name without `Model`, in snake case, plural. Every entity carries
   `@Table`, and a Konsist rule checks the name against the class, apart from an exception list in the test, each
   entry with its reason. An index or constraint name starts with its table's name.
6. **The schema's invariants a comment held are `CHECK` constraints**, written by hand in the baseline because Ebean
   generates one only for an enumerated column; a test reads them from the migrated schema.
7. **The history becomes one baseline generated from the models**, regenerated by each block of the lot, then
   append-only from the lot's merge.
8. **The pragma is set in the SQLite address**, so every connection carries it, the migration's included; a test
   reads production's address from its file.
9. **A migration may not drop a table a key references.** Ebean runs migrations in one transaction, where the pragma
   cannot be turned off, so the rebuild SQLite needs for most schema changes would cascade to the children. A test
   refuses such a script. The operator accepts the limit: rather than a path that turns the keys off outside the
   transaction, the database moves to PostgreSQL, whose `ALTER TABLE` changes a column in place, in the lot that
   follows this one, before ADR 0055's importer.
10. **A derived column leaves the schema without a replacement column**, but one: `archive_held`, a boolean, because
    whether bytes remain to delete is a fact no other column says. `media.animated` is read from the MIME type and the
    frame count rather than a `kind` column; `last_error` goes with no log in its place.

## Rejected

- **`RESTRICT` on `pins.publisher_id`**: SQLite checks it as soon as the person row goes, so deleting a user fails
  or passes depending on the order in which the cascade reaches `persons` and `pins`. Reproduced on sqlite-jdbc
  3.53.2.0 by the specification review (`.reviews/the-database-enforces-its-references-spec.md`).
- **`NO ACTION`**, which checks at the end of the statement: Ebean's `ConstraintMode` cannot declare it.
- **`CASCADE` on `pins.publisher_id`**: deleting a person would delete the pins they published.
- **Keeping the hand-written deletions beside the cascade**: every rule written twice.
- **A Konsist rule on the table name's form alone**: a renamed model would keep its old table silently, as
  `pin_tag_model` did.
- **A path that turns the keys off outside the migration's transaction**, for SQLite's rebuild: machinery that
  PostgreSQL makes useless, the move to it being a priority.
- **The pragma off during migrations through a second connection**: an in-memory test database is not shared between
  connections, and ADR 0012 keeps the datasource declared once, in properties.

## Consequences

- A table renamed apart from its model costs one line in the exception list, or one hand-edited migration: Ebean's
  generator reads a rename as a drop and a create.
- Until PostgreSQL, a referenced table (`users`, `pins`, `boards`, `persons`, `tags`, `user_data_imports`) changes
  only by what SQLite's `ALTER TABLE` does: add, rename or drop a plain column, and its indexes. A type, a
  nullability, a default, a `CHECK` or a key action waits. A later rebuild of
  any table carries its `CHECK` constraints by hand, the model files not recording them.
